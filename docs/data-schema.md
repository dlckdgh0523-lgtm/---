# 데이터 사전 — 익명 구조 데이터

> insurance-field-copilot이 수집하는 익명 구조 데이터의 정의·수집 경로·개인정보 판단 기준·활용 계획.
> 이 문서는 관리자 교차 분석 화면([/admin](../src/app/admin/page.tsx))과 내보내기([/api/admin/export](../src/app/api/admin/export/route.ts))의 근거다.

## 왜 이 데이터인가

보험사·GA별 **수수료 구조와 환수 조건은 공개 데이터가 존재하지 않는다.** 이 제품의 전략은 사용자가 입력한 구조값을 익명으로 축적해 회사별 기준을 역산하는 것이다. 금액(개인 재산)은 클라이언트에서 암호화하고, **회사 정책·계약의 구조적 속성만** 익명 수집한다.

## 수집 항목 (StructureRecord — 소속 구조)

| 필드 | 타입 | 의미 | 수집 조건 |
|---|---|---|---|
| `id` | string (UUID) | 서버가 부여하는 랜덤 식별자 | 저장 시 생성. **계정·이메일과 조인 불가** |
| `enteredBy` | `'user'` | 직접 입력 값만 저장(기본값 재집계 금지 = GIGO 방지) | 항상 'user' |
| `affiliation` | `'captive' \| 'ga'` | 전속 / GA | 소속 선택에서 파생 |
| `companyTier` | `captive-life \| captive-nonlife \| large-ga \| small-ga` | 소속 구분 4종 (회사명 아님) | 설정 B에서 선택 |
| `mainProductLine` | `life \| third \| general \| auto \| savings` | 주력 상품 구분 | 설정 B |
| `advanceRate` | number (0~1) | 선지급률 | **사용자가 직접 입력(structureSource='user')한 경우만** |
| `clawbackSchedule` | `{maxMonth, clawbackRate}[]` | 환수 구간표(유지 개월수별 환수 비율) | 직접 입력한 경우만 |
| `hasCompanyMinimum` | boolean | 회사 권장 최소치의 **존재 여부만** (금액 아님) | 최소치 > 0 여부 |
| `createdAt` | ISO string | 저장 시각 | 항상 |

## 수집 항목 (ContractStructureRecord — 계약 구조)

| 필드 | 타입 | 의미 | 수집 조건 |
|---|---|---|---|
| `id`, `enteredBy`, `createdAt` | (위와 동일) | | |
| `productLine` | ProductLine | 상품 구분 | 계약 입력 |
| `premiumBand` | `~5 \| 5~10 \| 10~20 \| 20~30 \| 30~50 \| 50+` | 월납 보험료 **구간**(정확한 금액 아님) | 계약 입력 시 금액을 구간으로 변환 |
| `factors` | ContractFactors | 4문항 응답(관계·부담·계기·자동이체) | 계약 입력 |
| `businessCategory` | string \| null | 사업장 업종(없으면 null) | 계약 입력 |
| `riskLevel` | `high \| medium \| low` | 클라이언트 결정론 판정의 **등급만**(점수·금액 없음) | 계약 입력 |

## 왜 이것이 개인정보가 아닌가

분류 기준은 **"개인의 재산 상태" vs "회사의 정책·계약의 구조적 속성"**이다.

- **수집 안 함(개인 재산, 클라이언트 암호화)**: 수령액·보유 현금·고정지출·목표 금액, 계약 선지급 금액 **원본**. 특정 개인의 재산이라 유출 피해가 크고 집계 가치가 없다.
- **수집함(회사 정책·구조 속성)**: 선지급률·환수 구간·소속 구분·상품·보험료 **구간**·4문항·업종·위험 **등급**. 소속사가 정한 정책 또는 계약의 구조적 속성이며 개인을 특정할 수 없다.
- **조인 불가**: 레코드에 이메일·계정 ID를 저장하지 않는다(랜덤 UUID만). 계정과 시스템적으로 연결되지 않는다.
- **서버 방어**: 프로필 수신 시 금액 필드를 능동 삭제한다(2중 방어).

## 마스킹 기준

| 임계값 | 상수 | 목적 |
|---|---|---|
| **k-익명성** | `K_ANON_MIN = 5` | 교차 필터 조합(셀)의 표본이 5건 미만이면 수치 차단 — **개인 특정 방지**. 조합을 좁히면 개인이 드러날 수 있으므로(예: GA대형×저축성 1명). |
| **통계 신뢰** | `STRUCTURE_MIN_SAMPLE = 30` | 30건 미만이면 "표본 부족"으로 표기, 프리셋에 미반영 — **통계적 신뢰 부족**. 두 임계값은 목적이 다르다. |

30건 근거: 중심극한정리의 통상적 경험칙(n≥30)에서 왔으며 이 도메인에 대한 실증 검증은 아니다 `[미검증 가설]`. 표본이 쌓이면 재검토한다.

## 향후 활용

1. **회사별 프리셋 자동화** — 소속 구분별 표본 30건 도달 시, 선지급률·환수 구간 중앙값을 신규 사용자 기본 프리셋으로 제공(현재는 공통 예시값).
2. **상품별 위험 프로파일** — 상품 × 환수 조건 교차로 "이 상품은 이 구간이 위험하다"를 데이터로 산출.
3. **GA 매칭 품질 개선** — 소속 구분별 구조 차이가 드러나면 설계사가 자기 조건을 다른 곳과 비교할 근거가 된다.

## 내보내기 스키마

`/api/admin/export?format=json|csv` — **집계값만**(개별 레코드 없음). 파일 상단에 `generatedAt`, 표본 수, 마스킹 기준을 포함한다. JSON은 `{ meta, data: CrossAnalysis }` 구조. CSV는 소속×선지급률·소속×환수 점검점·최소치 3블록.

## 정직 고지

- 골든셋(LLM 회귀 평가)과 이 구조 데이터는 별개다.
- 현재 실사용자가 사실상 개발자 1인이라 **표본이 0에 가깝고 통계적 의미가 없다.** 이 문서와 화면은 **수집·집계·마스킹·내보내기 구조가 동작함**을 보이는 것이 목적이다.
