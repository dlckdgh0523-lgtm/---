## 지역 데이터 로드맵

지역 데이터는 시군구 단위 팩(`public/data/regions/{시군구코드}/`)으로 관리하며, `npm run build:region -- --sigungu=11170` 한 번으로 한 지역을 멱등하게 생성·갱신한다. 어느 지역이 준비됐는지는 `public/data/regions/index.json`(레지스트리)이 단일 출처다.

**자동 수집 워커는 구현하지 않았다.** 공공데이터포털 파일데이터는 로그인 기반 수동 다운로드라 수집 자동화가 막혀 있기 때문이다. 다만 지역별 빌드 스크립트가 "인자 하나로 한 지역, 멱등 재실행 가능" 형태로 설계돼 있어, 수집 경로만 확보되면 스케줄러가 하루 한 지역씩 이 스크립트를 호출하는 것만으로 확장된다.

## 알림 채널 로드맵

- **이메일(Resend)이 주 채널이다.** 카카오를 쓰지 않은 이유: "나에게 보내기"만 검수 없이 가능하고, 타인에게 보내려면 비즈앱 전환과 검수가 필요하며 자동 발송 메시지는 반려 사유다 — 실제 사용자에게 전달 가능한 채널이 아니다. **카카오 알림톡은 사업자 계약이 필요해 개인 개발자가 붙일 수 없다.** 카카오톡 채널을 운영하는 조직에서는 채널 어댑터(`src/lib/notify`) 추가만으로 연결된다 — 현재는 email 구현체만 있고 slack·kakao는 인터페이스만 존재한다(미구현).
- **Resend 도메인 인증 전 제약**: 발신 주소는 `onboarding@resend.dev`로 고정되고 수신은 Resend 계정 소유자 본인 이메일로만 가능하다. 인증 후에는 `NOTIFY_EMAIL_FROM` 환경변수만 교체하면 된다.
- **구독자 저장소 한계**: 로컬 파일(`data/subscribers.json`) 기반이라 Vercel 서버리스(휘발성 FS)에서는 유지되지 않는다 — 프로덕션은 KV/DB로 교체 필요. 저장되는 것은 이메일·지역코드·동의 시각뿐이며 금액 데이터는 서버에 절대 없다.
- 스케줄: Vercel Cron(`vercel.json`)이 매일 오전 10시(KST)에 `/api/notify/daily`를 호출, 옵트인 사용자만 발송.

## LLM 통합 — 원칙과 기각한 대안

**절대 원칙**: 숫자는 전부 결정론적 코드가 만든다(금액·환수 노출·위험 점수·폐업률·채점 — 전부 코드). LLM은 이미 계산된 값을 받아 해석·문장 생성만 한다. LLM에 비밀을 주지 않는다 — 1차 방어는 타입 수준(`src/lib/llm/types.ts`에 금액·키 필드가 존재하지 않음), 2차 방어는 공통 출력 필터(`src/lib/llm/guard.ts`: 키 형태·내부 경로·재무 권고·가입 단정·법령 인용 차단).

**검토했으나 기각한 접근:**
- **파인튜닝 — 기각.** 학습 데이터가 없다. 실제 설계사-고객 상담 대화록 보유 0건이며, 확보하더라도 개인정보라 사용할 수 없다. 데이터 없는 파인튜닝은 근거 없는 복잡도 추가다. 페르소나 제어는 시스템 프롬프트 + 컨텍스트 + few-shot으로 충분하다.
- **멀티 에이전트 / LangGraph — 기각.** 에이전트 그래프가 필요한 수준의 분기나 장기 상태가 없다. 툴 콜링 단일 턴으로 충분하다. 증명할 수 없는 복잡도는 복잡도일 뿐이다.

**법령 데이터**: 국가법령정보 API는 도입하지 않기로 결정했다(2026-08-14). 법령 관련 기능 전체를 제외하며, 출력 필터의 법령 언급 차단은 유지한다 — LLM이 조문·과태료를 지어내는 것을 막기 위해서다.

**음성 롤플레잉 (모의면접 형태)**:
- 음성이 기본 모드, 텍스트는 폴백(SR 미지원·마이크 거부 시 동일 기능). 페르소나는 접점 지도에서 고른 실제 사업장 데이터 + 화면에 명시된 가상 설정(나이대·성격)으로 구성된다.
- **채점의 역할 분담을 정직하게 기록한다**: rubric(기준 5개·가중치)은 코드 상수로 고정돼 있고, 각 기준의 충족 "판정"은 LLM이 전사 인용과 함께 수행하며, 코드는 인용 검증(전사에 실재하는가, 저신뢰 발화가 아닌가)과 가중합·힌트 감점만 한다. 즉 점수의 산식은 결정론적이지만 판정 자체는 LLM 판단이다.
- 인식 오류 오염 방지: confidence 임계 미달 발화는 채점 근거에서 제외되고, 리뷰에서 전사를 수정하면 재채점한다. 세션 인식 실패율이 높으면 채점 신뢰도 경고를 붙인다. 모든 임계값은 [미검증 가설] 상수.
- **개인정보 예외 고지**: 브라우저 음성 인식(Web Speech API)은 구현체에 따라 음성 데이터가 브라우저 제공사 서버로 전송될 수 있다. 이 앱은 금액 데이터를 서버로 보내지 않는 설계지만 음성은 그 예외이며, 시작 전 화면에서 명시하고 동의를 받는다.
- 효과 측정 한계: 롤플레잉 점수와 실제 계약률의 상관관계는 측정할 수 없다. 앱 내 지표(세션 완료율·힌트 사용 추이·반복 세션 점수 변화)는 "영업 실력"이 아니라 "이 도구에 대한 숙련"을 측정한다.

## 로그인 / 데이터 접근 구조 (2026-08-14 확정)

**매직링크 대신 일반 로그인(이메일+비밀번호)을 택했다** — 매직링크는 로그인할 때마다 메일함을 확인해야 하는 반복 비용이 있고, 현장에서 하루에도 여러 번 여닫는 도구에는 맞지 않는다.

**계층 구조:**

| 계층 | 내용 | 수명 |
|---|---|---|
| 계정 | 이메일 + 인증 해시 + 생성 시각만 저장 (이름 등 추가 개인정보 수집 안 함). Redis(Upstash), 로컬은 파일 폴백 | 영구 |
| 세션 | JWT(HS256) httpOnly 쿠키. API는 인증 여부만 확인 | 7일 |
| 금고 | 금액 데이터(계약)의 클라이언트 AES-GCM 암호화 + 메모리 키 | 30분 무활동 시 잠김 |

**비밀번호 하나로 두 가지 키 (서로 파생 불가):**

```
비밀번호 ── PBKDF2(salt="ifc-auth-v1:<email>")  → authProof → 서버 전송 (서버가 다시 scrypt로 해시해 저장)
         └─ PBKDF2(salt="ifc-vault-v1:<email>") → 금고 키   → 브라우저 메모리에만 (전송 안 됨)
```

- **원문 비밀번호는 브라우저를 벗어나지 않는다.** 서버가 받는 것은 로그인 검증용 파생 해시(authProof)뿐이다. 서버 코드에는 `password`라는 식별자 자체가 존재하지 않는다 (코드 검색으로 확인).
- 로그인 성공 = 금고 자동 열림. 사용자가 별도 패스프레이즈를 외울 필요가 없다.
- **금고 잠금(30분 idle)**: 클릭·키입력·스크롤이 30분 없으면 키와 복호화된 금액 데이터를 메모리에서 지우고 잠금 화면으로 전환한다. 오버레이로 가리는 방식이 아니라 컴포넌트 언마운트로 참조를 끊는다. 해제는 비밀번호 재입력 → 서버 재검증(로그인 라우트 재사용) → 키 재파생. JWT 세션은 이 타이머와 무관하다 — 접점 지도 등 금액 없는 화면은 잠금 중에도 쓸 수 있다.
- 계약 데이터는 localStorage에 AES-GCM 암호문(`{iv, ct}`)으로만 저장된다 (평문 저장 경로 삭제, 구버전 평문은 첫 열림 때 암호화 이관).
- **정직한 한계**: ① JS는 메모리 명시 소거를 보장하지 못한다 — 추출 불가 CryptoKey + 참조 절단이 브라우저에서 가능한 최선이다. ② 프로필(보유현금 포함)은 크로스 기기 요구(2026-08-13 결정)로 서버에 평문 저장돼 있다 — 금고가 보호하는 것은 로컬 계약 데이터와 화면 표시이며, 프로필 금액의 클라이언트 암호화(서버는 암호문만 보관)는 미결 결정 사항이다. ③ 서버가 클라이언트 JS를 서빙하므로 악의적 서버 운영자까지 방어하는 모델은 아니다 — 이 설계의 목표는 "서버 로그·DB 유출 시 원문 비밀번호와 계약 금액이 없다"이다.

**이메일 구독은 계정과 분리** — 알림은 계정 없이 이메일+지역만으로 등록/해제되는 별도 저장소를 쓴다. 계정과 구독 이메일이 같아도 시스템적으로 묶지 않는다 (목적이 다르다: 계정=데이터 접근, 구독=콘텐츠 수신).

**롤플레잉 리밋**: 계정(JWT) 기준 30회/일, Redis INCR+EXPIRE 카운트 (인스턴스 간 공유). 별도 브라우저 토큰 체계는 만들지 않았다 — 로그인이 이미 있으므로.
